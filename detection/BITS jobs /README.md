
# T1197 : BITS Jobs (Persistence / Defense Evasion)

| Field | Value |
|---|---|
| MITRE ATT&CK | [T1197 - BITS Jobs](https://attack.mitre.org/techniques/T1197/) |
| Tactics | Persistence (TA0003), Defense Evasion (TA0005) |

---

## Description

BITS (Background Intelligent Transfer Service) is a legitimate Windows service used by Windows Update, Office, Edge, SCCM/Intune and other updaters to download or upload files asynchronously. Jobs are managed through `bitsadmin.exe`, the PowerShell BITS cmdlets (`Start-BitsTransfer`, `Add-BitsFile`, `Set-BitsTransfer`...) or the COM API (`IBackgroundCopyManager`).

Adversaries abuse it for three reasons:

1. **Stealth download**: traffic is generated by `svchost.exe` (BITS service), not by the attacker's process, and it uses the system proxy settings and resumes after network loss.
2. **Persistence**: a job lives in the BITS queue database and **survives reboots** (default job inactivity timeout is 90 days). It can be configured to launch a program with `/SetNotifyCmdLine` when the job completes or fails.
3. **Execution without a visible parent**: the notify command is spawned by the BITS service, so the parent process is `svchost.exe -k netsvcs -p -s BITS` instead of the attacker's tool.

## Attack Scenario

1. The attacker gets a foothold as a user (or admin).
2. Create a job: `bitsadmin /create /download <JobName>`.
3. Add the file to fetch: `bitsadmin /addfile <JobName> <URL> <LocalPath>`.
4. Set the command to run on completion/error: `bitsadmin /SetNotifyCmdLine <JobName> <Program> <Params>`.
5. Optionally tune retries: `bitsadmin /SetMinRetryDelay <JobName> <seconds>`.
6. Start the job: `bitsadmin /resume <JobName>`.
7. The job stays in the queue across reboots; the notify command is executed by the BITS service every time the job completes/errors.

## Attack Artifacts

| Artifact | Where |
|---|---|
| `bitsadmin.exe` process with `/create`, `/addfile`, `/SetNotifyCmdLine`, `/SetMinRetryDelay`, `/resume`, `/transfer` | Sysmon 1, Security 4688 |
| PowerShell `Start-BitsTransfer`, `Add-BitsFile`, `Set-BitsTransfer -Asynchronous` | PowerShell 4104 |
| Job creation / transfer start / error / completion with job name, URL and owner | `Microsoft-Windows-Bits-Client/Operational` |
| Job stored in the BITS queue database | `%ALLUSERSPROFILE%\Microsoft\Network\Downloader\qmgr.db` (older: `qmgr0.dat` / `qmgr1.dat`) |
| Temporary file `BIT*.tmp` created in the destination folder, then renamed to the final file | Sysmon 11 |
| Network connection and DNS query from `svchost.exe` (BITS) to the payload host | Sysmon 3 / 22 |
| Child process whose parent is `svchost.exe -k netsvcs -p -s BITS` (the notify command) | Sysmon 1 |


## Investigation

1. **Identify the job**: on the host run `bitsadmin /list /allusers /verbose` or `Get-BitsTransfer -AllUsers | fl *`. Collect: name, owner, state, URL, local file, notify command line, creation and modification times.
2. **Timeline in Splunk** around the alert: process tree (who ran `bitsadmin`/PowerShell), Sysmon 3/22 from `svchost.exe` to the URL, Sysmon 11 for the downloaded file, Bits-Client events 3/59/60/61 for the job.
3. **Analyse the payload**: hash the downloaded file and the notify command binary, check reputation, detonate in a sandbox if needed.
4. **Check persistence**: the notify command line and `/SetMinRetryDelay` value. A job in error state retrying against a dead URL with a notify command is a strong indicator.
5. **Contain and remediate**: remove the job (`bitsadmin /reset /allusers` or `Get-BitsTransfer -AllUsers | Remove-BitsTransfer`), delete the dropped files, isolate the host if the payload was executed, reset the account if compromised.

## False Positives

- Windows Update, Microsoft Defender, Office, Edge, Teams and Store updates (BITS jobs to Microsoft CDN domains).
- SCCM/MECM, Intune and WSUS software distribution.
- Third-party updaters that rely on BITS (some vendor agents, backup or deployment tools).
- Administrators or installation scripts using `bitsadmin /transfer` or `Start-BitsTransfer` for plain downloads.

Tuning: allow-list destination domains and known parent processes for download rules. Keep `/SetNotifyCmdLine` and children of the BITS service as high-fidelity, since legitimate use is rare.
